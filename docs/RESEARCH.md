# UI/UX 자료 조사

페이지를 더 보기 좋게 만들 방법을 찾다가 3D·애니메이션 자료 여섯 곳을 조사했다.
**무엇을 쓸지가 아니라 무엇을 안 쓸지**를 정하는 것이 목적이다.

조사일: 2026-08-03

## 판단 기준

이 사이트에는 제약이 하나 있고, 그게 대부분의 답을 결정한다.

> `index.html` 하나. 빌드 없음, 프레임워크 없음, 외부 요청은 GitHub 아바타 하나.
> 근거는 [STACK.md](STACK.md)

그래서 자료를 볼 때 기능이 아니라 **결과물이 무슨 형태로 나오는지**를 먼저 봤다.
이미지로 나오면 그냥 쓰면 되고, React 컴포넌트로 나오면 스택을 바꿔야 한다.

여기에 하나 더. 이 페이지는 인스타그램에서 눌러 들어와 몇 초 머물다 나가는 곳이다.
첫 화면이 뜨는 속도가 화려함보다 중요하다.

## 조사한 자료

| 자료 | 정체 | 결과물 형태 | 가격 |
|---|---|---|---|
| [Shapefest](https://shapefest.com/) | 레이트레이싱 3D 오브젝트 10만+ | PNG 이미지 | 무료 |
| [Craftwork](https://craftwork.design/free/3d-assets) | UI 키트, 3D 일러스트 | 주로 Figma 소스 | 무료 섹션 있음 |
| [GetLayers](https://www.getlayers.ai/) | AI 워크플로용 템플릿·3D 씬 | 3D 씬은 단독 HTML, 템플릿은 Next.js | 유료 |
| [Animmaster Lib](https://animmasterlib.dev/) | 애니메이션 컴포넌트 약 300개 | HTML/CSS/JS, React/Next | 유료 (평생) |
| [Spline](https://viewer.spline.design/) | 브라우저 3D 저작 도구 | `<spline-viewer>` 웹 컴포넌트 | 무료 티어 |
| [Skiper UI](https://skiper-ui.com/) | shadcn/ui용 컴포넌트 | React + Tailwind + Framer Motion | 무료/유료 |

## 분류

### 지금 스택 그대로 쓸 수 있다

- **Shapefest** — 이미지 한 장이라 `<img>` 하나면 끝난다. 의존성이 안 늘어난다.
  원본이 고해상도라 리사이즈와 압축은 필요하다
- **Craftwork 무료 3D 에셋** — 같은 방식. 양은 Shapefest보다 훨씬 적다

### 붙기는 하지만 값이 비싸다

- **Spline** — 스크립트 태그 하나로 붙어서 빌드가 필요 없다. 문제는 무게다.
  [공식 문서](https://docs.spline.design/doc/how-to-optimize-your-scene/doczPMIye7Ko)가
  "웹은 5MB 이하를 목표로" 라고 안내한다. 지금 페이지 전체가 5KB 미만이다
- **Animmaster Lib** — 순수 HTML/CSS/JS 파트는 이식할 수 있다.
  다만 간판 기능인 **페이지 전환 효과는 단일 페이지에 쓸 자리가 없다.**
  스크롤·호버·텍스트 애니메이션만 쓰자고 결제하기엔 남는 게 적다

### 스택을 바꿔야 한다

- **Skiper UI** — React + Tailwind + shadcn 전제. 도입하면 빌드 단계가 생기고
  단일 파일 구조가 깨진다. 링크 몇 개짜리 페이지에 치를 값이 아니다
- **GetLayers** — 3D 씬은 단독 HTML이라 붙지만 템플릿 쪽은 Next.js.
  AI 도구에 붙여넣는 프롬프트를 파는 서비스라 성격도 이 프로젝트와 다르다

## 결정

**Shapefest만 채택한다. 나머지는 보류한다.**

이미지 한 장은 되돌리기 쉽고, 안 맞으면 태그 한 줄 지우면 그만이다.
반면 Spline이나 Skiper UI는 한 번 들이면 구조가 따라 바뀌어서 무르기 어렵다.
지금 단계에서 그만한 확신이 없다.

**판단 — 지금 페이지가 밋밋한 원인은 3D가 없어서가 아니라 내용이 없어서다.**
조사 시점의 페이지는 링크 카드 세 개가 전부 `링크 이름 / 짧은 설명`에 `href="#"`
이었다. 여기에 3D 씬을 얹으면 빈 페이지에 비싼 액자를 두르는 셈이 된다.
자료를 붙이는 것보다 내용을 채우는 쪽이 체감 차이가 크다.

## 적용 순서

1. [x] **링크와 문구 채우기** — 실제 URL과 설명. 여기서 차이가 제일 크다
2. [ ] **Shapefest 오브젝트 하나** — 프로필 영역에 배치. 표시 크기의 2배로 리사이즈하고
   100KB 아래로 압축한다. 재질은 clay·matte 계열, 색은 톤다운된 것 하나.
   지금 팔레트(`#faf9f7` 계열)에서 glass·metal은 반사가 강해 붕 뜬다
3. [~] **CSS만으로 되는 것** — 라이브러리 없이 직접 쓴다.
   워드마크 타이포는 넣었다. 카드 진입 애니메이션과 배경 질감은 아직이다

Spline은 페이지가 채워진 뒤에도 여전히 하고 싶으면 그때 다시 본다.
붙일 때는 poster 이미지와 lazy load를 걸어 조건부로 넣는다.

## 레퍼런스 페이지 계측

개인 페이지 세 곳을 보고 실제 전송량을 재봤다. 구조가 셋 다 다르다.

| | 종류 | 만든 방식 | 전송량 | 요청 |
|---|---|---|---|---|
| 관문형 | 이름 + 문 세 개, 내용은 뒤에 | 손 | — | — |
| 단일 화면형 | 한 화면에 이력과 링크 전부 | 손 | 3,826 KB | 7 |
| 롱스크롤형 | 섹션 여러 개짜리 포트폴리오 | Framer (노코드) | 1,416 KB | 54 |

이 사이트는 **단일 화면형**이다. 관문형은 뒤에 놓을 페이지가 먼저 있어야 성립하고,
롱스크롤형은 파는 것이 있는 사람(프리랜서)의 구조다.

**배운 것 — 한글 페이지의 무게는 대개 폰트다.** 단일 화면형 쪽 3,826 KB를 뜯어보니
HTML 문서는 14.5 KB고 나머지 3,811 KB가 전부 웹폰트(Pretendard) 파일 다섯 개였다.
캔버스 파티클 배경, 그라데이션 로고, 반응형 처리까지 전부 합쳐 14.5 KB다.

원인은 Pretendard를 **static** 버전으로 부른 것이다. 대안이 이미 있다.

```
static/pretendard.min.css                 전체 글리프를 받는다
static/pretendard-dynamic-subset.min.css  페이지에 실제로 쓴 글자만 받는다
```

dynamic subset은 Google Fonts가 한글에 쓰는 방식이다. 한 줄 교체로 수십 KB까지 내려간다.
**이 사이트에서 나중에 한글 웹폰트를 쓰게 되면 반드시 dynamic subset 쪽으로 간다.**

### 코드에서 가져온 것

- **자간 + 대문자로 만드는 워드마크** — 큰 글씨에 자간을 벌리고 그 아래 작은 대문자를
  같은 방식으로 두면, 이미지나 웹폰트 없이 워드마크가 된다. `.name` 과 `.role` 에 적용했다

  다만 같이 쓰이는 **`text-indent` 자간 보정은 넣지 않았다.** 레퍼런스 소스가
  `letter-spacing` 과 같은 값을 `text-indent` 에 넣어 "마지막 글자 뒤 자간 때문에
  가운데 정렬이 밀리는 것"을 상쇄하고 있었는데, 실제로 재보니 보정 없이 좌우가 맞았다.
  30px 기준 `text-indent: 0` 에서 좌 126.14px / 우 126.14px, `.16em` 을 넣으면
  좌 128.53px / 우 123.75px 로 오히려 오른쪽으로 밀린다. 브라우저가 마지막 글자 뒤
  자간을 이미 처리하고 있다.

  **레퍼런스에서 본 기법은 그대로 옮기기 전에 재본다.** 차이는 2.4px 라 눈으로는
  구분이 안 되고, 재보지 않으면 반대 방향으로 고친 줄도 모른다
- **정보 층 나누기** — 역할 / 이력 / 링크를 각각 다른 형태로 둔다.
  특히 이력은 링크가 아니라 텍스트 목록이다. 현재 작업은 별도 층으로 빼지 않고
  이력 맨 위에 둔다 → [PLAN.md](PLAN.md)

가져오지 않은 것은 어두운 네온 배색과 캔버스 파티클이다. 개발자 페이지가 대부분 그 방향이라
밝은 톤이 오히려 덜 흔하고, 파티클은 배터리를 계속 쓴다. 인스타그램에서 눌러 들어와
몇 초 머무는 페이지에는 값이 맞지 않는다.

## 안 한 것

- 카드 아이콘을 3D 이미지로 교체 — 지금은 인라인 SVG라 요청이 0개인데 카드 수만큼
  이미지 요청이 생기고, 24px 크기에서는 3D 렌더가 뭉개진다. 지금이 낫다
- 어두운 네온 배색으로 전환 — 개발자 페이지가 대부분 그쪽이라 밝은 톤이 오히려 덜 흔하다.
  따뜻한 오프화이트를 유지하고 기법만 가져왔다
