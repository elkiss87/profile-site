## 4. 페이지 규칙

내용을 고칠 때마다 다시 정하지 않도록 적어둔다.

### 구조는 세 층이다

**역할 한 줄 / 이력 목록 / 링크 카드.** 성격이 다른 것을 같은 형태로 만들지 않는다.

- **이력**은 링크가 아니라 **읽는 목록**이다. 타이틀을 카드로 만들면 개수만큼 페이지가
  길어지는데, 텍스트로 나열하면 뭘 만든 사람인지가 몇 초에 읽힌다
- 최신이 위로 온다. 진행 중인 것은 맨 위에 두고 기간을 `2025–` 처럼 열어둔다.
  끝이 열린 기간이 진행 중을 말하므로 별도 표시는 붙이지 않는다
- 현재 작업을 목록 밖으로 빼서 강조하는 방식도 있는데, 그건 **이력이 열 줄쯤 넘어
  목록 안에 묻힐 때** 필요한 처리다. 그때 다시 본다
- **링크 카드**는 실제로 눌러서 갈 곳만 둔다

### 표기

- **위는 Engineer, 아래는 Programmer.** 맨 윗줄은 자기소개라 업계 밖에서도 읽히는
  말이 낫고, 이력은 실제 크레딧이라 게임업계 관례를 따른다
- **미발표 프로젝트 이름은 쓰지 않는다.** 회사명까지만 적는다
- **회사명을 줄마다 붙이지 않는다.** 타이틀 이름만으로 어디 작품인지 읽히고,
  모르는 사람에게는 적어줘도 의미가 없다. 줄마다 붙이면 이력서가 되고 모바일 폭도
  못 버틴다. 소속이 갈리는 지점은 **항목 사이 여백**으로만 표시한다
- **사내 시스템 설계는 적지 않는다.** 타이틀과 기간까지다

### 없는 곳을 가리키는 카드는 만들지 않는다
