같은 배포 자리를 두고 부딪힌다. 큐가 꼬인 원인이 이것으로 보인다.
`gh api .../pages --jq .build_type` 이 `workflow` 면 전환된 것이다.

**저장소 루트를 통째로 올리면 문서까지 서비스된다.** `elkiss.me/CLAUDE.md`,

개인 도메인에서 작업 문서 원본이 열릴 이유는 없다. 필요한 두 파일만 담는다.

**유령 실행이 배포를 붙잡고 있었다.** 큐에 걸린 실행 하나가 취소·강제취소·삭제 모두
403/409 로 거부됐고, 조회 엔드포인트마다 상태가 다르게 나왔다. 손댈 방법이 없어 두었는데,
그동안 배포가 **6분 39초**씩 걸렸다. `deploy-pages` 가 `deployment_in_progress` 를
반복해서 받는 상태였다. Pages 는 저장소당 배포를 하나씩 처리하므로, 죽은 실행이 그 자리를
잡고 있으면 다음 배포가 기다린다.

시간이 지나 풀린 뒤 다시 재보니 **19초**로 끝났다.
브랜치 방식(42~49초)보다도 빠른데, 파일 14개 대신 2개만 올리기 때문이다.

**유령 실행 자체는 아직 남아 있다.** 배포 자리는 풀렸지만 실행은 `queued` 인 채
`updated_at` 이 멈춰 있다. Actions 목록에만 남는 것이고 새 배포는 막지 않는다.
지울 방법은 GitHub 지원 문의뿐이다. Pages 가 `workflow` 방식이라 이 자동 워크플로는
다시 돌 일도 없다.

**배포가 이상하게 느리면 남아 있는 실행부터 본다.** 워크플로나 액션을 의심하기 전에
`gh run list` 로 끝나지 않은 실행이 있는지 확인한다.

## 2026-08-05

시각 작업. 3D 오브젝트는 만들었다가 뺐다.

- 진입 애니메이션 — 워드마크가 **글자 단위로** 들어오고, 이어서 역할·이력·카드·푸터 순
- 배경에 아주 옅은 그라데이션과 필름 그레인(SVG 노이즈, data URI)
- 카드 hover 시 2px 떠오르고 그림자가 지며 아이콘과 화살표가 함께 움직인다
- 푸터 링크 밑줄이 hover 때 왼쪽에서 자라난다
- 3D 오브젝트 → [RESEARCH.md](RESEARCH.md)

**전부 CSS다. 외부 요청은 그대로 0개다.** 배경 이미지를 구할까 하다가 접었는데,
이 페이지는 여백이 지탱하고 있어서 이미지를 깔면 타이포가 눌린다. 색과 움직임은
무게가 0인데 효과는 그만큼 나온다.

**`prefers-reduced-motion` 을 존중한다.** 움직임을 줄이도록 설정한 사용자에게는
애니메이션과 transition 을 통째로 걷어낸다. 어지럼증 때문에 그 설정을 쓰는 사람이 있다.

**hover 로만 드러나는 것은 터치 기기에서 대안을 준다.** 푸터 밑줄은 마우스를 올려야
나타나는데, 터치 기기에는 그 계기가 없다. `@media (hover: none)` 에서는 밑줄을 항상
보이게 둔다. 그러지 않으면 모바일에서 링크인 줄 모른다.

**워드마크를 글자로 쪼갤 때는 `aria-label` 을 함께 단다.** 없으면 스크린리더가
`E, L, K, I, S, S` 로 낱글자를 읽는다. 쪼개도 자간과 가운데 정렬은 그대로였다
(좌 126px / 우 126px).

**만들어보고 빼는 것은 낭비가 아니다.** 3D 오브젝트는 화면에 얹어보고 나서야
필요 없다는 판단이 섰다. 다만 순서는 바꿀 수 있었다 — 원본을 임시로 얹어 눈으로 먼저 보고
그 다음에 압축했다면 압축 작업 자체가 필요 없었다.

## 2026-07-30

`elkiss.me` 를 GitHub Pages에 연결. 1차 목표 달성.

- 도메인은 Cloudflare Registrar에서 구매. 원가 판매라 갱신 때 가격이 안 뛴다
- `@` 와 `www` 둘 다 CNAME으로 걸고 **DNS only(회색 구름)** 로 둔다.
  프록시를 켜면 GitHub의 도메인 검사가 통과하지 못한다
- HTTPS까지 확인하고 Enforce HTTPS 적용
- DNS 설정에서 세 번 막혔다 → [TROUBLESHOOTING.md](TROUBLESHOOTING.md)
- 문서를 넷으로 쪼갰다. PLAN은 "무엇을", DEPLOY는 "어떻게", DOMAIN은 "왜",
  TROUBLESHOOTING은 "막혔을 때". 한 파일에 다 있으면 실제로 배포할 때 찾기가 어렵다

**배운 것 — DNS는 안 되면 기다리기 전에 조회부터 한다.** 세 번 다 "전파가 늦나" 하고
기다렸는데 실제로는 설정이 빠져 있었다. `nslookup <name> 1.1.1.1` 한 줄이면 갈렸다.
